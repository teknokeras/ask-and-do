Larkspur has a small data model. This page explains each object and how they relate.

Organization

An organization is the top-level container. Every user, group and project belongs to exactly one organization. A token always acts inside one organization, so the API never needs an organization ID in the path.

Users

A user is a person (or a service account) with an account in your organization. Each user has an email address, a display name, a role and a status. User IDs start with usr_.

Invitations

An invitation is an offer to join the organization, sent by email. It is not a user yet: the person becomes a user only when they accept. Invitation IDs start with inv_. See Inviting users.

Groups

A group is a named set of users, such as a team. Groups are how you give several people access to a project at once. A user can belong to any number of groups. Group IDs start with grp_.

Projects

A project is a unit of work with an owner, a short key such as PAY, and a visibility setting. Projects are shared with groups, not with individual users. Project IDs start with prj_.

Roles

Every user has one organization-wide role: admin or viewer. Admins can change things; viewers can only read. There are no per-project roles. See Roles.

How they fit together

Organization
├── Users ──── belong to ──► Groups ──── have access to ──► Projects
├── Invitations (become users when accepted)
└── Projects (each owned by one user)
