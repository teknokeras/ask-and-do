There are two ways to update a group, and they behave differently. Read this page before using either one.

Update fields (PATCH)Replace the group (PUT)
EndpointPATCH /v1/groups/{group_id}PUT /v1/groups/{group_id}
Fields you leave outKeep their current valueAre cleared
Changes membersNoYes, sets the full member list
Use it toRename a group or edit its descriptionSync a group from another system

Update fields (PATCH)

A PATCH changes only the fields you send. It accepts name and description. Members cannot be changed with PATCH; use the members endpoints.

curl -s -X PATCH http://localhost:8000/v1/groups/grp_7d2e91b0 \
  -H "Authorization: Bearer $LARKSPUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Platform Engineering"}'

This renames the group and leaves the description and members as they were.

Replace a group (PUT)

A PUT replaces the whole group with what you send. You must send name, and the request also sets the description and the complete member list.

Fields you leave out of a PUT are not kept. If you omit description it is cleared. If you omit members, every member is removed from the group.

curl -s -X PUT http://localhost:8000/v1/groups/grp_7d2e91b0 \
  -H "Authorization: Bearer $LARKSPUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Platform", "description": "Platform engineering",
       "members": ["usr_4f9a2c1e", "usr_0b7c55d2"]}'

PUT is meant for tools that keep a group in sync with a list kept somewhere else, such as an HR system. For a quick rename, use PATCH.

Rules for both

  • Only admins can update groups.
  • The same naming rules apply as when creating a group.
  • The group ID never changes, so project access is kept.
