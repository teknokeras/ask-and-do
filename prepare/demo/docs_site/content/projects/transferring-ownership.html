Every project has exactly one owner. You may need to change owners when someone changes teams, and you must do it before removing a user who owns projects.

Transfer one project

Set a new owner_id with a partial update of the project:

curl -s -X PATCH http://localhost:8000/v1/projects/prj_51c0de77 \
  -H "Authorization: Bearer $LARKSPUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"owner_id": "usr_0b7c55d2"}'

Transfer all projects of a user

The transfer endpoint moves every project a user owns to another user in one call, including archived projects. Its path is short for "transfer": POST /v1/users/{user_id}/xfer. The user in the path is the current owner.

curl -s -X POST http://localhost:8000/v1/users/usr_4f9a2c1e/xfer \
  -H "Authorization: Bearer $LARKSPUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to_user_id": "usr_0b7c55d2"}'

The response lists the IDs of the projects that were moved:

{"transferred": ["prj_51c0de77", "prj_a90e3f12"], "to_user_id": "usr_0b7c55d2"}

Rules

  • Only admins can transfer projects.
  • The new owner must be an active user. Transferring to a deactivated user fails with 422 user_deactivated.
  • Transferring a user's projects to themselves fails with 422 validation_failed.
  • Group access does not change. The new owner can see the project because they own it.
  • An archived project can be moved with the transfer endpoint, but not with PATCH, since archived projects cannot be edited.
