Larkspur has two roles. Every user has exactly one, and it applies to the whole organization.

Admin

Admins can read and change everything in the organization: users, invitations, groups and projects. Admins can see every project, including private projects that are not shared with any of their groups.

Viewer

Viewers can read, but not change anything. They can list users, groups and group members, and see the projects visible to them (see Project access). Viewers cannot see invitations.

A viewer cannot change anything, even about their own groups or the projects they own. Every write request with a viewer token fails with 403 forbidden.

How roles are enforced

The API reads the role from the caller's token and checks it on every request. A client cannot raise its own permissions by sending a different role in the request body or a header. The full list of which role may call which endpoint is in the permission matrix.

Custom roles

Larkspur does not support custom roles or per-project roles. If you need some people to manage only certain projects, that is not possible today: only admins can change projects.

Changing a role

See Changing roles. Role changes apply to new tokens only.
