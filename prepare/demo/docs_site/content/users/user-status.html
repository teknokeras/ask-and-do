Every user has a status: active or deactivated. People with a pending invitation have no status because they are not users yet; see Inviting users.

Active

An active user can sign in and use any token issued to them.

Deactivated

A deactivated user cannot sign in, and the API rejects their tokens with 401 unauthenticated, including tokens that have not expired yet. Everything else is kept:

  • They stay a member of their groups.
  • They keep ownership of their projects.
  • Their email address stays reserved, so nobody else can be created or invited with it.

Deactivated users cannot be added to new groups (422 user_deactivated) and cannot receive project transfers.

Deactivate a user

Deactivation is the reversible way to take access away, for example while someone is on leave. Only admins can deactivate users. You cannot deactivate yourself.

curl -s -X POST http://localhost:8000/v1/users/usr_4f9a2c1e/deactivate \
  -H "Authorization: Bearer $LARKSPUR_TOKEN"

Reactivate a user

curl -s -X POST http://localhost:8000/v1/users/usr_4f9a2c1e/reactivate \
  -H "Authorization: Bearer $LARKSPUR_TOKEN"

A reactivated user gets back exactly the groups and projects they had before.

Deactivate or remove?

If the person is leaving for good, remove them from the organization instead. Removal cannot be undone; deactivation can.
