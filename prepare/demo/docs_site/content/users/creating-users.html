Creating a user makes an active account immediately. The person does not have to accept anything. Use this when you already know who the person is, for service accounts, or when moving people over from another system. If you want the person to confirm and choose their own display name, send an invitation instead.

Create vs invite

Create a userInvite a user
EndpointPOST /v1/usersPOST /v1/invitations
Account activeImmediatelyOnly after the person accepts
Display nameSet by the adminChosen by the person
Email sentA sign-in link, valid for 24 hoursAn invitation, valid for 7 days
Can be undoneDeactivate or remove the userRevoke the invitation before it is accepted

Request

Only admins can create users.

curl -s -X POST http://localhost:8000/v1/users \
  -H "Authorization: Bearer $LARKSPUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "lee@example.com", "name": "Lee Park", "role": "viewer"}'

Fields

FieldRequiredNotes
emailYesMust not belong to another user in the organization.
nameYes1 to 100 characters.
roleNoadmin or viewer. Defaults to viewer.

What happens next

Larkspur emails the new user a sign-in link. The link is valid for 24 hours. If it expires, the user can request a new one from the sign-in page; you do not need to create the account again.

Errors

  • 409 email_taken: a user with this email already exists. Look them up with GET /v1/users?q=lee@example.com.
  • 422 validation_failed: a field is missing or invalid.
  • 403 forbidden: your token has the viewer role.
