Every request to the Larkspur API needs a bearer token in the Authorization header. There is no anonymous access.

curl -s http://localhost:8000/v1/users \
  -H "Authorization: Bearer $LARKSPUR_TOKEN"

Base URL

All endpoints are under http://localhost:8000/v1. The API only accepts JSON request bodies; send Content-Type: application/json with every request that has a body.

Getting a token

Tokens are issued by your organization's sign-in service. Larkspur checks tokens but does not issue them, and there is no endpoint to create a token.

What a token contains

A token is a signed JSON Web Token (JWT). Larkspur reads three claims from it:

ClaimMeaning
subThe user ID of the caller, such as usr_4f9a2c1e.
roleadmin or viewer. See Roles.
expExpiry time. Tokens are valid for 60 minutes.

Because the role is in the token, role changes apply to new tokens only.

When a token is rejected

The API answers 401 unauthenticated when the header is missing, the token is expired or badly signed, or the user in sub is deactivated or no longer in the organization. Get a new token and retry. A valid token without the needed role gets 403 forbidden instead.

Keeping tokens safe

  • Do not put tokens in URLs. The API ignores tokens passed as query parameters.
  • Do not commit tokens to source control or paste them into tickets.
  • Tokens cannot be revoked one by one. To cut off a user's tokens at once, deactivate the user.
